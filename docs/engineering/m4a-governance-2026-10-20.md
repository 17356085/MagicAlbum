# M4A 社区管理实施与验收记录

2026-10-20。本地实现和回归已完成，真实容器验收尚待本批提交的远程 CI。本文不是 M4A 全部通过或全部阶段完成的声明。

## 权限与数据边界

- 新增五张持久化表：一次性引导标记、管理员角色、版主分区、发言限制、操作审计；迁移 `20261020.1` 同时给分区增加归档状态，`20261020.2` 增加举报处理理由。
- JWT 继续表示身份。每次管理操作读取数据库当前权限；配置邮箱只引导首位管理员，角色撤销后重启不应重新授权。保留至少一个管理员。
- 版主只能列出并审核授权分区的举报，评论继承父线程当前分区。修改角色、分区或限制的接口仅允许全局管理员。`/admin/me` 保留原管理员语义；`/governance/me` 返回当前账号的完整权限概况。
- 归档分区保留历史阅读，常规发帖和评论接口拒绝新增、编辑及移入；发言限制拒绝新增和编辑，保留登录、阅读和作者删除行为。期限可为空，表示持续限制；到期后按当前时间自动失效。
- 审核隐藏与恢复通过内容 owner 执行。作者删除的内容不可恢复；恢复评论要求父线程正常。线程恢复递增内容版本并写入既有 `THREAD_UPSERTED` 事件，评论继续使用既有状态和缓存机制。
- 理由须为去除两端空白后的 1–500 字符。审核结果和审计同事务提交；相同处理动作及理由重复提交不增加版本或审计，冲突动作返回 409。审计只包含操作者、动作、目标、理由、时间及请求 ID，不保存正文或密钥。

## 并发和模块接口

管理变更使用单例策略行锁；限制变更随后锁用户，分区变更随后锁分区。普通作者写入按用户 → 分区共享读锁 → 线程 → 评论锁定，线程移动涉及的分区按 ID 升序锁定。不同作者可以在同一分区并行写入；归档使用独占分区锁，等待已有写入事务结束。作者写入不获取全局策略锁。审核按策略 → 举报 → 父线程 → 评论锁定，取得线程行后复核当前分区。

治理模块为用户/分区行锁和分区配置管理增加五条源文件与目标类精确白名单。它们限定在 `GovernanceService` 与 `SectionGovernanceRepository`；不放开整个模块，也不允许治理直接写线程或评论。帖子和评论仍由内容 owner 保存状态及事件。Redis 分区缓存仅在数据库提交后清除，Redis 故障不回滚已提交的管理变更。

## 页面

新增社区管理页面，包括成员查询、管理员与分区版主授权、发言限制、分区创建/编辑/归档和审计分页。举报页面增加必填理由、已隐藏/已恢复筛选和恢复操作。手机“我的”和桌面侧栏按服务器返回的当前权限显示入口。

失败保留表单；403 不退出登录。请求使用会话、认证代次和请求序号保护，账号切换清理旧账号草稿，迟到的查询或写入结果不能回填新账号界面。导航展示与归档分别标注，不将“导航不显示”称作内容保密。

## 真实运行门禁与待办

新增独立 `community-runtime` CI，复用 M3 已验证的 Compose 生命周期和清理边界。计划严格执行 23 项：启动/构建 3、HTTP/SQL 12、手机竖横屏日夜浏览器 8。浏览器必须实际提交分区表单以及隐藏和恢复举报，再通过接口读回；截图同时检查日夜主题和横向溢出。必须执行完精确用例集合，无失败、错误、跳过，清理通过且八张截图齐全，才允许成功。

运行涵盖管理员引导、跨区拒绝、撤权后旧 Token 与重启、最后一位管理员保护、归档/发言限制、隐藏/恢复/作者删除/父线程规则、重复请求、SQL 审计和数据持久性。该门禁使用真实 MySQL/RabbitMQ/应用；搜索只记录 HTTP 与当前 SQL 结果，不冒充独立 Elasticsearch 验收。Elasticsearch 的故障、重建与同步仍由既有独立搜索任务回归。

本机 Docker 曾返回引擎错误，本批不重置 Docker 或关闭用户应用。远程推送后须核对本提交 CI 和实际产物，再补充结论。M4B 的任务化真实摘要、真机/Safari/系统软键盘专项和所有阶段结束后的整体审查及恢复回归仍未完成。
