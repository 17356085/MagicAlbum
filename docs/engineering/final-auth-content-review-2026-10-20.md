# 最终复审：身份绑定与内容生命周期

2026-10-20。本文记录整体复审中的追加修复，不代表所有阶段已经完成。真实外部模型、真机与 Safari 专项仍需独立验收。

## 登录身份

第三方登录原先可能按资料邮箱复用本地账号。现在只有 `provider + externalId` 的已有持久化绑定可以复用账号；Google/Apple 明确返回 `emailVerified=true` 时，新账号才保存真实邮箱。该邮箱已占用时返回 409，要求使用原登录方式，不自动合并。GitHub 的当前资料接口不证明邮箱所有权，使用随机 `@oauth.invalid` 联系邮箱；缺失或未验证的 Google/Apple 邮箱同样处理。独立事务与并发首次登录的失败回滚、赢家读回仍须回归。

新增 `email_verified`、`phone_verified` 两个非空、默认 false 字段。历史行和密码注册账号不自动获得验证标记；修改具体联系方式时清除对应标记。Cognito 必须返回完整认证结果及非空 access token 才能进入本地身份处理，新账号只标记实际通过 OTP 的联系方式。已有账号的对应联系信息未验证时拒绝 OTP 登录，仍可使用原登录方式；本批不增加账号合并或联系方式验证界面。不能把这种兼容限制描述为已经完成旧账号迁移验证。历史外部账号绑定也没有自动解绑或追溯证明，应在真实上线前人工核查。

首次管理员初始化同样不能信任未验证的邮箱登记。运维可设置 `APP_ADMIN_USER_ID` 精确选择已经可信登录并读回的用户；同时填写邮箱时必须匹配该用户。仅使用 `APP_ADMIN_EMAIL` 时要求邮箱已验证。非法 ID、账号不存在、邮箱不一致或邮箱未验证均拒绝启动且不授予角色。新配置不会在每次请求覆盖数据库角色，一次性治理初始化仍负责防止重启恢复已撤销权限。运行夹具通过真实注册、密码登录与 ID 一致性读回选择管理员，不通过修改验证字段绕过校验。

应用自身的短期 OAuth code 增加 S256 绑定：发起标签页生成随机 verifier，仅将 challenge 经授权入口绑定到 state；回调换取应用 code 时保留 challenge，最终 POST 交换同时提交 verifier。错误证明不消费合法 code；正确证明只允许消费一次；升级前缺少绑定的 state/code 拒绝。前端同一标签页还须持有对应 provider、未过期的会话记录，旧回调不得覆盖更新的登录。

这是应用 code 与浏览器发起记录的绑定，不能据此声称上游所有 OAuth 提供商已启用 PKCE 或已经真实登录验收。协议设计参考 [OAuth 安全最佳实践 RFC 9700](https://www.rfc-editor.org/info/rfc9700/) 与 [S256 定义及测试向量 RFC 7636](https://www.rfc-editor.org/rfc/rfc7636.html)。受控回归与真实 Redis Lua 执行分别验证；外部 OAuth/Cognito 凭据和提供商行为不在受控测试的证明范围内。

验证码、OAuth code 和二维码交换失败属于独立认证挑战，不能因其 401 清除已有有效登录。二维码扫描、确认等受保护操作仍执行正常 bearer 失效处理；请求路径按实际 pathname 精确匹配，不被查询字符串中的登录路径误导。

## 回复与审核

作者删除回复改为不可恢复的 `DELETED` 墓碑，保留归属线程，待处理举报仍能定位分区并被驳回；审核恢复仅接受 `HIDDEN`。公开详情、列表、引用不返回删除正文，缓存命中也复核引用父回复状态。现有 status 为 VARCHAR，没有新增状态 CHECK 迁移的必要。

回复写入、编辑、删除、点赞及审核采用线程后回复的加锁顺序，写操作必须取得实际写锁；正常线程可见性与读列表/计数条件一致。帖子详情、列表、搜索与作者投影补全正常回复数量，避免这些入口一直显示零。禁言不额外扩展到点赞，作者删除的既有豁免保持。

## 明确保留的边界

- 密码修改没有新增全局 token 撤销机制，原令牌仍按既有最长 120 分钟有效期处理，不能宣称立即踢出所有会话。
- 当前网关后的 IP 限流没有新增可信代理配置；公网部署需单独定义可信来源，不能直接相信任意转发头。当前 Compose 使用 local profile 与关闭人工验证的开发配置，不是生产部署模板。
- 隐藏或删除帖子不撤销已发出的公开图片 URL；当前媒体资源是公开资源契约，不具备私密附件或云端 ACL 生命周期保证。
- S3 写入结果不确定时保守保留原图，没有宣称完成原图孤立对象治理或外部对象存储备份。本地恢复与媒体门禁分别证明各自范围。

## 本轮验收

主代理负责检查委派实现的差异、迁移和验证证据，再执行最终代码的完整回归。新增真实 MySQL 断言检查旧用户验证字段仍为 false、字段非空且默认 false。真实 Redis 门禁执行生产 OAuth 交换 Lua，检查错误证明保留、一次消费、重放、过期和旧记录拒绝；不会以模拟 JWT 或源码存在代替真实外部身份验收。
