# M4B 摘要任务实施契约

2026-10-20，实施前冻结。本文定义后续实现边界，不代表代码、真实模型或阶段验收完成。M4A 的结果继续以阶段记录和对应提交的 CI 为准。RAG、AI 服务独立拆分和公网发布不在本批范围。

## 任务与内容所有权

新增 `ai_summary_task`、`ai_summary_attempt`、`ai_summary_budget`、`ai_summary_request` 四张表，分别保存任务、每次执行、按 UTC 日期的用户预算和成功请求的幂等绑定。最后一表是在实施审查时补充：非 force 请求直接命中已有完成摘要时，也必须绑定新请求键，防止同一键后来被用于其他帖子。任务 ID 使用 UUID；绑定线程 ID、内容版本、触发者和原始请求幂等键。执行记录保留尝试序号、租约 owner、provider/请求模型/响应模型、供应商关联 ID、用量、预留与计入额度的数量、耗时和固定失败类别；不保存正文或密钥。

核心仍拥有内容与权限。AI 模块通过 content owner 的快照/条件写回接口读取与更新摘要，不直接操作 Thread Entity/Repository。线程增加当前摘要任务 ID；内容版本递增时清除当前任务指针和派生摘要，旧任务的回调必须拒绝覆盖。旧线程 ID 队列和消费者由版本化任务队列替代，普通发帖不再自动触发有成本的模型调用。迁移明确清理旧租约及不具备版本证明的派生摘要；不修改帖子正文。

状态：`IDLE`（尚未请求）、`PENDING`、`PROCESSING`、`COMPLETED`、`FAILED`、`CANCELLED`、`SUPERSEDED`。任务及执行记录持久化；消息只携带 UUID，领取和完成在短事务中进行，模型调用在事务外执行。接受结果要求当前任务、内容版本、正常内容状态、owner 和有效租约同时匹配。

## HTTP 和页面

- 保留 `GET /api/v1/ai/summary/{threadId}`，登录用户可读取正常公开帖子的当前摘要。增加按 UUID 查询的任务入口；旧任务不得泄露旧版本或隐藏内容正文。
- `POST /api/v1/ai/summary/{threadId}?force=false|true` 要求作者或当前分区管理权限，以及 UUID 格式的 `Idempotency-Key`。相同触发者/幂等键必须返回同一任务；目标、版本或 force 不一致返回 409。已在处理的任务不隐式接管；重新生成须等待终态，或显式取消后使用新幂等键。
- `POST /api/v1/ai/summary/{threadId}/tasks/{taskId}/cancel` 使用同一当前权限规则，重复取消幂等。取消先提交状态，再尽力取消本实例的 HTTP 传输；跨实例及供应商已收到的请求不能保证中断或退款。
- 查询/触发/取消返回直接对象，包含 `threadId, taskId, contentVersion, taskContentVersion, status, summary, canManage, attempts, errorCode, provider, model, inputTokens, outputTokens, usageEstimated, chargedTokens, requestId, updatedAt`。可空字段明确返回 null，摘要无可用正文时返回空字符串。
- 前端使用新任务 ID 和幂等键，网络结果不确定时重试保留请求标识和原 force 值；已收到持久化失败终态后的主动重试使用新键。轮询串行、不重叠，离页与账号切换取消请求并拒绝迟到结果。显示生成、失败、取消和额度不足；普通读者不显示管理动作，Mock 明确标注测试模式。保留手机触控、键盘和减少动效约定。

## 权限、预算和恢复

触发/领取/取消按用户 → 父线程 → 任务锁定；预算行通过同一用户行锁协调，不增加普通内容写入的全局锁。领取时重新核对触发者当前授权；排队后撤权不得继续发起模型调用。

每用户最多两个未结束任务，执行消费者每实例最多两个；跨实例的用户预算及任务保护由数据库执行。默认单次输入最多 12000 字符、输出 512 tokens、请求最多 120 秒、租约 180 秒。自动尝试最多三次，仅针对传输、超时、429 和供应商 5xx；鉴权、参数、空结果或无效响应不自动重试。请求及响应体设上限，异常信息不包含供应商正文、地址中的凭据或密钥。

每次外部尝试开始前预留额度。输入使用包含系统提示在内的保守估算，并加输出上限；供应商给出实际用量时记录并结算，未报告或结果不确定时保留预留值并标记估算，不虚报实际计费金额。失败、超时及处理中的取消不自动退还不确定费用；未领取就取消不发起请求。重试每次独立记账，不能绕过预算。UTC 日期绑定本次尝试，不因完成时跨日而写错预算。

`chargedTokens`是该任务所有尝试的计入额度之和；只要任一次仍是估算，`usageEstimated`就保持true。`inputTokens/outputTokens`仅代表最后一次尝试的供应商报告值，不把之前不确定的调用伪装成准确用量。额度以token单位控制，不能当作供应商账单金额或绝对费用上限。

持久化的 PENDING 与过期 PROCESSING 由恢复轮询重新投递原任务 ID；重复消息不能增加有效并发或重复结算。过期 owner 不能完成新租约。恢复、取消、编辑及晚回均保留可审计执行记录。

每轮恢复扫描固定资格时间，在20条UUID分页期间使用同一快照；扫描耗尽后从头开始新一轮。新到期的较小UUID进入下一轮，发布失败保留当前游标和快照。

## 验收证据

先用受控协议服务验证用量、超时/失败、重试、取消、旧版本晚回、并发重复与额度耗尽，并执行真实 MySQL/RabbitMQ/应用的运行门禁。再从私有配置调用外部模型，至少覆盖正常与长文本，回读持久化任务、摘要、版本和用量；记录模型效果、耗时及预算口径。受控 HTTP 服务与 Mock 不计为真实外部模型，凭据不上传 CI 或写入证据文件。完整链路与分层验证分别说明，不能互相冒充。
