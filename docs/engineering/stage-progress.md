## M0 的实施范围

1. **运行与测试入口**：统一根目录 Python 测试配置路径，增加一个独立账号的真实浏览器旅程；新增 GitHub Actions 容器浏览器任务。
2. **账号本地状态**：最近浏览按账号清除与切换；发帖草稿按账号或访客隔离；身份未确定时停止持久化；切换时取消旧的自动保存，旧提交结果不能清空新账号内容。历史遗留的无归属草稿不自动分配给当前账号。
3. **完整部署**：四个应用生产镜像、三个依赖容器；支持独立宿主机端口，核心服务等待通知服务健康；修复前端构建上下文、pnpm 构建许可文件和 Nginx 健康检查地址。
4. **浏览器业务链路**：注册、登录、发帖、评论、点赞、收藏与取消、通知已读和跳转、举报。关键持久化结果由 API 回读，并包含跨账号拒绝操作。
5. **恢复与运行样本**：源应用停止写入后转储两个逻辑库和上传目录；恢复到独立项目，比较表数据与文件 SHA-256，再通过应用读回账号、帖子、收藏和图片。资源与五次顺序延迟采样仅用于诊断。

复现方式、参数和产物说明见[M0 运行时验收维护说明](m0-runtime-verification.md)。本机证据保存在 `outputs/m0-20261015/`，属于被忽略的本地文件，不保证出现在克隆仓库中。

历史快照（2026-10-15）：前端 122 项、Java 239 项、工程检查器 9 项测试通过；当时浏览器完整旅程与独立恢复受内存阻塞，没有通过。该阻塞已由下方 10-17 完整复验记录收口，不能把此历史状态作为当前结论。

先检查现有实现和调用方，再按边界实施。每批都保留独立的验收结果，不把服务拆分和界面重写混在一次变更中。

| 顺序 | 任务 | 验收要求 |
| --- | --- | --- |
| 1 | 梳理编辑器、图片上传、发布失败与重试的状态 | 网络失败保留正文；重复提交有明确处理；跨账号与卸载后的异步回调不会污染新状态 |

| 3 | 固化用户、内容、互动、通知、媒体模块的内部接口 | 写清数据归属、事务边界和授权入口；架构检查覆盖禁止的跨域依赖 |

| 5 | 形成 M1 验收记录，冻结 M2 契约 | 不影响 M0 浏览器链路；明确内容事件的版本、隐藏语义、幂等键、重建与回退策略 |

## 微服务和 Go 的实施约束

- 核心 Java 应用继续拥有账号权限、帖子主数据和媒体任务创建，先把内部边界做清楚。
- M2 的内容事件与既有通知专用 Outbox 分别定义契约；不能直接把通知负载当作通用内容事件。
- M3 第一个 Go 服务限定为异步媒体 worker。Java 持久化任务，Go 处理图片并携带任务标识和版本回传，Java 校验归属并持久化结果后才确认完成。
- 服务独立部署必须同时带来契约测试、幂等、超时重试、健康检查、日志和回退路径；仅新增目录或进程不算拆分完成。
