# M1 手机使用方式调研与改版依据

## 阶段和调研边界

当前处于 M1「社区体验与模块边界」，未进入 M2。上一批主要确认窄屏布局和部分键盘行为；“控件放得下”不足以说明适合手机使用。本次在已推送 `62adfbd` 及其后的本地草稿修复之上继续，不覆盖已有改动。

采用场景假设：用户在通勤或休息时用手机触屏浏览中文兴趣帖子，常用操作是切换内容、搜索、读帖、回复和短篇发帖；较少频繁调整主题或退出账号。此假设来自产品定位，不是已有访问统计或用户访谈结论。

调研包括公开设计规范、现有页面与调用分析、任务流程检查。没有真实用户访谈或远程真机接入，不能把规范推导称为用户研究已验证。

## 来源与取舍

| 来源 | 可用于本项目的结论 | 实施取舍 |
| --- | --- | --- |
| [Android 布局与导航](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns) | 紧凑屏幕的主导航支持同级 3–5 个目标；较少使用的操作适合逐步展开 | 手机底栏保留发现、分区、动态、排行、我的五个同级页面；桌面继续使用既有侧栏 |
| [Apple 标签栏](https://developer.apple.com/design/human-interface-guidelines/tab-bars) | 标签栏用于目的地导航，操作应使用工具栏等入口；标签应稳定可用 | 发帖不冒充导航标签，作为独立操作；受保护页面继续复用既有登录守卫 |
| [Android 无障碍](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility) | 触控目标至少 48dp，文字对比度至少 4.5:1 | 网页触控主入口采用 48 CSS px，次级控件至少 44 CSS px；dp 与 CSS px 不是物理等价换算，仍需真机体验验证 |
| [Apple 布局与安全区域](https://developer.apple.com/design/human-interface-guidelines/layout) | 尊重系统安全区域；以渐进展开降低选项密度 | 底栏与固定操作避开底部安全区域；主题、退出、历史等集中在我的；不删掉功能 |
| [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) | 软键盘可能缩小可见视口，而布局视口不变 | 检查输入焦点和可见视口变化，避免固定导航/按钮覆盖输入；不把桌面缩小窗口宣称为真实软键盘验证 |

## 现有问题

1. 顶部同时堆叠品牌、搜索、主题、发帖、通知、头像、退出和另一排导航。为了适配 320px 曾缩小间距和按钮，增加误触，常用导航离拇指较远。
2. 账号操作常驻阅读界面，而收藏、浏览历史、我的帖子等手机入口不集中；桌面侧栏被隐藏后功能发现成本上升。
3. 发帖页面默认展示多行格式按钮、大输入框和空白预览，手机需要先滚过工具区，再在输入与预览间往返。
4. 浮动 AI 入口会占据正文、输入框或底部操作位置；手机需要一个可主动访问的入口，而非始终遮挡内容。
5. 列表底部分页包含手动页码框，主次操作相近；长标题、作者及元信息需要按阅读优先级重新安排。

## 实施边界

先重做共享手机导航、账号入口、发帖/编辑/回复的共用编辑器、列表阅读和详情回复可达性。业务 API、权限、上传和草稿账号隔离保持既有语义；不引入手势专属功能或假通知数据。桌面结构继续沿用。

验收不再仅检查横向溢出：覆盖触控目标、底栏位置、任务入口可达、输入焦点与视口变化、预览切换、直接访问和历史返回、日夜主题；保留桌面回归。真实手机浏览器和软键盘若未执行，将明确列为待验证。

## 实施结果

手机和紧凑窗口（小于 1024px）使用独立的操作层级。这个边界与既有桌面侧栏出现的位置一致，并覆盖常见手机横屏；不把较宽的手机横屏直接切回桌面工具条。

| 任务 | 本次结果 |
| --- | --- |
| 浏览与切换 | 顶栏仅品牌、搜索和通知；底部五个稳定目的地；列表独立发帖入口；正文与列表标题优先，手机分页突出上一页/下一页 |
| 我的内容 | 新 `/me` 集中个人主页、帖子、评论、收藏、历史、设置、主题和退出；访客查看历史沿用现有登录要求并保存登录后目的地 |
| 发帖/编辑 | 首先进入编辑，预览按需切换；四项主工具单行，更多格式展开；可选标签折叠；提交/草稿入口和完整状态提示位于 sticky 页头 |
| 长帖回复 | 常驻查看评论/写回复；写回复聚焦现有 composer；未登录直接打开登录弹层；评论高频按钮增大，页码使用数字键盘提示 |
| 输入 | 文本输入聚焦时收起底栏/固定回复条；可见视口参数用于浮层高度与底部偏移；手机 AI 入口移入我的，不常驻遮挡正文 |
| 返回 | 子页面手机顶栏常驻返回入口，使用 Vue Router 的站内历史状态判断返回，修复 SPA 内跳转但 referrer 为空时无法回到来源的问题；不承诺跨分页评论定位 |

保留冰蓝/靛蓝主题、已有 API、上传与异步响应保护、账号草稿隔离；没有新增后端接口或微服务，也没有把本地改动推送到远端。

## 验证与剩余限制

完整前端单测 237 项通过；类型检查、lint、生产构建通过。手机任务、布局与键盘检查共 57 项，以最终 `browser.xml` 为准：覆盖三种手机尺寸和横屏、五种布局宽度、日夜主题，并检查 48px 主入口、正文输入、预览切换、发布错误反馈、长帖回复、登录弹层、主题、聊天入口、退出取消和返回筛选列表。所有 API 使用固定数据，浏览器本地草稿可读回；没有借此宣称真实发布、真实通知或后端权限通过。

本地产物在被忽略的 `outputs/mobile-redesign-20261018/`：单元测试 JSON、浏览器 JUnit/日志、布局与触屏截图、工程引用检查。人工查看了发现、发帖、夜间排行、我的和长帖阅读截图。

已修复集成测试发现的输入焦点与全局样式冲突，最终需要保持全套回归通过。实体 iPhone/Android、Safari、系统软键盘动画、真实安全区、放大字体及慢网体验尚未验收。通知/评论跨页定位、核心领域契约、请求关联和 Outbox 观察仍属于未完成的 M1 范围；不能因此宣布 M1 已完成或进入 M2。
