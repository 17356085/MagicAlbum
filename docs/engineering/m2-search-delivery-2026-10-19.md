# M2 搜索与可靠内容事件交付记录

更新日期：2026-10-19。M2.1 的持久化边界已由提交 `5a22ed5` 的真实 MySQL CI 验证；本批扩展消息发布、搜索、重放与重建。最终真实服务验收结果在完成后补充，本文件的实现说明不单独作为通过证据。

## 实现与边界

- **可靠发布**：独立内容事件 Outbox 在同一 owner 事务内记录版本；发布领取使用数据库条件更新和租约，网络 I/O 在领取事务外执行。只有 persistent、mandatory 路由成功且 correlated confirm ACK 才标记 PUBLISHED。失联、过期领取和达到重试上限均保留可诊断状态，管理员可重试 FAILED。
- **搜索**：Elasticsearch 只保存内容投影，按当前版本单调更新；相同事件幂等，旧版本不能覆盖新版本，同版本身份冲突进入失败处理。隐藏和删除保留不含正文的永久墓碑，避免历史事件复活内容。搜索命中经 owner 当前状态和版本重新核对后才组装响应。
- **故障回退**：依赖不可用、未就绪、指针不一致或候选过期时，使用直接数据库查询。它保留现有 API 参数、分页和创建时间排序；数据库 LIKE 与 CJK 全文检索的匹配能力不同。新增索引的最终一致性延迟可能暂缺候选，不承诺立即可搜。
- **重放与隔离**：消费成功后 ACK；失败经过有限重试进入持久化失败队列。重放确认新投递后才确认旧消息。无效 envelope 转为仅含摘要和安全标识的隔离记录，隔离成功后继续处理同批合法消息。
- **完整重建**：持久化 gate 暂停所有参与内容事件的 writer，并等待已取得共享 gate 的事务提交；扫描全部 owner 投影、核对计数和每个文档后切换 alias。没有把自增 ID 当作提交顺序。旧物理索引保留，切换不确定时核对实际指向；无法确认一致就保持数据库回退。
- **部署**：默认关闭搜索，单独的 Compose override 启用内部 Elasticsearch。核心 owner 数据仍由 Java/MySQL 持有，本阶段没有把搜索模块拆成独立微服务。权限、功能开关和恢复操作见 [M2 搜索运维说明](m2-search-operations.md)。

## 验收设计

1. 默认 Java 回归验证现有业务、发布状态机、投影、消费、回退、重放和维护 gate。
2. MySQL 专项从合法旧库升级至 `20261019.2`，验证原事件 delivery 字段回填、唯一约束、真实 owner 事务和外部 SQL 回读。
3. `scripts/ci/content-search-smoke.sh` 使用独立 MySQL、RabbitMQ 和 Elasticsearch，四轮分别执行正常链路、仅索引停机、broker 与索引同时停机、原存储重启恢复。每轮要求一项真实执行的 JUnit 用例，无失败、错误或跳过。
4. 正常链路包含修改/标签过滤、乱序/重复/身份冲突、隐藏删除墓碑、confirm 与 returned 区分、写入后 ACK 前断连、租约过期重领、隔离后继续重放，以及低 ID 事务晚提交时的完整重建。
5. 运行脚本保留服务版本、资源配额、JUnit、阶段数据回读和清理报告；仅删除由本次随机标识拥有的临时容器和匿名卷，凭据不写入提交或验收产物。

这些阶段是有状态的验收流程，不把一项聚合用例中的多个断言虚报为独立测试数量。MySQL 升级/事务专项为 7 项独立用例加 1 次确定性复跑；搜索专项为四轮各一项聚合用例。M2 完成必须要求四轮都实际执行并通过，以及最终 owner/索引/队列回读一致。正常链路通过不能替代重启恢复通过。
