# 架构工程规范与决策

同频在同一个工作区维护核心、网关、通知、聊天实时与媒体进程。跨域调用、替换基础设施和修改运维入口时，交付应覆盖现有调用方、数据语义和故障恢复。

| 规范 | 变更要求 | 验收证据 |
| --- | --- | --- |
| ARCH-01 · 依赖方向 | 让业务用例依赖业务接口。由基础设施实现依赖 RabbitMQ、Kafka、数据库或对象存储的调用 | 检查受影响的入口、用例、仓储与适配器。仓库的 Java 检查用于验证跨域 `entity` 和 `repo` 依赖 |
| ARCH-02 · 业务端口 | 按实际业务语义定义端口。事件发布须区分接收确认、明确失败和结果未知 | 对比现有适配与候选适配。在相同输入下比对业务结果和故障后的重试行为 |
| ARCH-03 · 数据归属 | 由唯一业务方更新权威状态。跨进程访问经受权接口或事件。读模型和索引遵循同一权限和版本约束 | 使用实际运行账号检查跨库访问。联合验证单一写入端、幂等和回退 |
| ARCH-04 · 事件协议 | 业务事实与按收件人发送的通知意图分别定义。事件保留稳定标识、协议版本、聚合版本和时间 | 回归重复、乱序、格式错误、重放和版本变更。用两条载体验证同一事件标识和最终结果 |
| ARCH-05 · 版本化迁移 | 用 Flyway 定义每种方言的结构迁移。保留已发布版本和运行账号权限边界 | 验证全新安装和存量版本升级。跨引擎迁移前后核对关键表、游标和序列 |
| ARCH-06 · 部署配置 | 默认部署沿用已验收的配置。新的可选适配器显式开启，凭证从部署环境提供 | 验证默认部署、试点部署和相应回退配置。检查公开入口与内部入口权限 |
| ARCH-07 · 适配器验证 | 先运行正常入口回归，再用真实依赖验证适配器。故障测试覆盖外部提交成功而本地确认丢失的情况 | 保存版本、命令、测试报告、业务读回和清理结果。区分本地试点和目标环境发布 |
| ARCH-08 · 决策记录 | 重大技术选择记录背景、取舍、结果和回退条件。密钥与生产数据保留在部署环境 | 评审时引用决策和验收报告。替代旧决策时保留其历史链接 |

## 其他基础设施的替换边界

搜索消费、回放和重建通过 `ContentSearchIndex` 访问派生索引。当前实装为 Elasticsearch。若验证 OpenSearch，需要提供对应适配器并实测索引映射与分词、版本冲突、别名双向切换、查询和聚合，同时与内容 owner 的数据核对。此轮 OpenSearch 交付覆盖接口与验证范围。[索引端口](../../backend/src/main/java/com/example/demo/search/port/ContentSearchIndex.java)

Redis 同时承担缓存、会话或令牌状态以及限流等职责。替换只读缓存之前，按用途点清 TTL、失效通知和回源路径。替换会话或限流存储时，另外验证原子更新、并发计数和故障后的权限语义。此轮缓存替换交付覆盖依赖边界。网关首页的短期公开数据缓存由应用进程管理。[Redis 键与用途](../../backend/src/main/java/com/example/demo/common/RedisKeys.java) · [缓存失效](../../backend/src/main/java/com/example/demo/common/RedisCacheEvictor.java)
