# ADR-003 · 实时会话核验的双协议边界

浏览器通过 WebSocket 向 Go 实时进程提交会话凭证。核心服务持有验证令牌与会话的权威逻辑，实时进程只获取账号 ID 和到期时间。选取这个单次内部调用验证 Java 和 Go 共用一个版本化契约，浏览器继续使用同一连接协议。

默认通过内部 HTTP 核验。隔离试点可以同时给 Java 启用 gRPC 监听、给 Go 配置 gRPC 地址和凭证。两种入口调用同一个核心核验用例。Protobuf `v1` 字段编号固定，账号 ID 和到期时间用整数。新增兼容字段时使用新编号，删除字段时保留编号和名称。

容器部署的 gRPC 使用私网、TLS 及单独的服务凭证。Go 校验服务端证书和服务器名称，限制连接和调用耗时。认证拒绝、超时和服务不可用分别处理。试点故障时，核验关闭式失败。回退时同时撤掉 Java 监听和 Go gRPC 配置，并重新部署 Go，继续由既有 HTTP 核验入口提供服务。

压测样例在一个 Go 进程内使用已建立连接的本机端口，比较同样消息的 HTTP/JSON 和 gRPC/Protobuf 编解码与往返开销。实际部署还需核对跨语言连通、TLS、权限与浏览器重连。测试样本和部署证明记录在各自的执行报告。

在仓库根目录执行以下命令重跑协议对照。结果给出单次耗时、分配字节与分配次数，可用于比较两种协议的本机调用成本。

```bash
cd services/chat-realtime
go test -run '^$' -bench BenchmarkSessionVerificationHTTPAndGRPC -benchmem -benchtime 500ms -count 3
```
