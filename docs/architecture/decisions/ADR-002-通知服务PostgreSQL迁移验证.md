# ADR-002 · 通知服务的 PostgreSQL 迁移验证

## 背景

通知服务独立管理通知记录和 SSE 游标。更换数据库时必须延续原通知 ID、幂等键、已读状态和每个用户的流游标。

## 决策

继续复用通知 API、业务用例和通用 JDBC 查询。启用 `postgresql` profile 时选择 PostgreSQL 驱动、独立 Flyway 目录和游标行初始化方言。MySQL 使用原版本迁移和方言。

停写后，在一份一致的数据库快照中读取通知、用户游标和事件三个业务表，按外键依赖顺序导入已经完成迁移的空库。逐表比较行数和按主键排序的 SHA-256。PostgreSQL 重新设置通知 ID 的生成起点。验收完成前保留原库。试点回退使用新建的空 MySQL 库，反向迁移并复核 PostgreSQL 新增的记录和游标。

## 影响与验收

切流时暂停通知写入及核心 Outbox 投递。切流和回退测试覆盖幂等重放、并发游标、原游标续订以及写入后关闭旧进程。生产环境采用何种维护窗口与回退数据同步方式由实际规模和发布评审确定。
