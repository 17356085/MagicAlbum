# 2026-04-30 k6 并发测试计划归档

## 归档结论

已将并发测试纳入 `perf/` 压测体系，覆盖三类测试：

- 阶梯并发测试：10 / 25 / 50 / 100 / 200 VU
- 稳态并发测试：默认 50 VU 连续 30 分钟，可切换 100 VU / 15 分钟
- 读写比例并发测试：`WRITE_RATE=0 / 0.1 / 0.2 / 0.5`

新增执行脚本：

- `perf/run-concurrency-tests.sh`

新增方案文档：

- `perf/CONCURRENCY.md`

更新入口文档：

- `perf/README.md`

## 执行命令

### 阶梯并发测试

```bash
bash perf/run-concurrency-tests.sh step
```

默认每档：

- 2 分钟升压
- 15 分钟稳态
- 2 分钟降压

总耗时约 95 分钟。

### 稳态并发测试

```bash
bash perf/run-concurrency-tests.sh soak
```

默认：

- 50 VU
- 30 分钟稳态
- 总耗时约 34 分钟

100 VU / 15 分钟示例：

```bash
SOAK_VUS=100 SOAK_DURATION=15m bash perf/run-concurrency-tests.sh soak
```

### 读写比例并发测试

```bash
bash perf/run-concurrency-tests.sh write-matrix
```

默认：

- 50 VU
- `WRITE_RATE=0 / 0.1 / 0.2 / 0.5`
- 每档约 19 分钟
- 总耗时约 76 分钟

### 全量执行

```bash
bash perf/run-concurrency-tests.sh all
```

默认全量耗时约 205 分钟，不含镜像构建、服务启动和结果整理。

## 观测指标

### k6 指标

- `http_req_duration p(95)`
- `http_req_duration p(99)`
- `http_req_failed`
- `http_reqs`
- `iterations`
- `checks`

### 服务端指标

- API HTTP 5xx / 429
- 接口级 P95/P99
- JVM CPU、heap、GC、线程数
- Hikari active / idle / pending / max connections
- MySQL QPS、连接数、慢查询、锁等待
- RabbitMQ 发布/消费速率、队列堆积

## SLA 判定

默认 SLA：

- P95 <= 300ms
- P99 <= 500ms
- `http_req_failed` <= 0.1%

首次出现任一指标不达标的 VU 档位，记录为首次 SLA 失效点。

## 执行建议

建议不要一上来执行 `all`。更稳妥的顺序：

1. 先跑 `step`，找到首次 SLA 失效点。
2. 选择失效点以下一档跑 `soak`。
3. 在稳定档位上跑 `write-matrix`。
4. 对 429 单独统计，确认它属于预期限流还是业务失败。
